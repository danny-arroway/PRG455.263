### 1. Why M5UI, Not Tkinter

Tkinter is a desktop GUI library — it depends on a full operating system
windowing layer (X11 / Win32 / Cocoa) and the complete CPython standard
library. The CoreS3 runs **MicroPython**, a stripped-down interpreter with
no windowing system underneath it; it drives its screen directly over SPI.
There is no `tkinter` module, and there's no practical way to add one on a
microcontroller with this little RAM and flash.

**M5UI** is the framework that actually runs on the device. It's built on
top of **LVGL** (Light and Versatile Graphics Library), an embedded GUI
engine used widely across microcontroller projects. Conceptually it's very
close to Tkinter: you create widget objects, position them, style them,
and attach event callbacks to them. The syntax is different; the mental
model — widgets + events — is the same one you already have.

### 2. The M5UI Programming Model

Every M5UI program follows the same skeleton:

```python
import os, sys, io
import M5
from M5 import *
import m5ui
import lvgl as lv

page0 = None

def setup():
    global page0
    M5.begin()
    Widgets.setRotation(1)     # landscape
    m5ui.init()                # must be called before creating any widgets
    page0 = m5ui.M5Page(bg_c=0xFFFFFF)

    # ... create widgets here, all with parent=page0 ...

    page0.screen_load()        # actually display the page

def loop():
    M5.update()                 # pumps touch/IMU/etc. and the UI redraw

if __name__ == '__main__':
    try:
        setup()
        while True:
            loop()
    except (Exception, KeyboardInterrupt) as e:
        try:
            m5ui.deinit()
            from utility import print_error_msg
            print_error_msg(e)
        except ImportError:
            print("please update to latest firmware")
```

Two things to internalize immediately:

- **`m5ui.init()` before any widget is created**, and every widget you
  create should be given `parent=page0` (or another widget) so it belongs
  to the page you load.
- **`M5.update()` must run every loop iteration.** This is what actually
  processes touch input and redraws the screen. If you forget it, your
  UI will look frozen even though your program is running.

**Two ways to react to touch**, and you'll use both this lecture:

| Approach | What it gives you | When to use it |
|---|---|---|
| **Widget events** (`add_event_cb`) | High-level: "this button was pressed", "this checkbox changed" | Almost always — this is how real UIs are built |
| **Raw touch** (`M5.Touch`) | Low-level: raw (x, y) coordinates, touch count | Custom drawing, gestures, or when you need to know *where* on the screen, not just *which widget* |

### 3. Widget Reference

Each widget below is shown as a small, standalone, runnable snippet.
Assume `page0` already exists from the skeleton above unless noted.

#### 3.1 `M5Label` — displaying text

```python
title_label = m5ui.M5Label(
    "PRG455 Lecture 3",
    x=10, y=10,
    text_c=0x000000,      # text color
    bg_c=0xFFFFFF,         # background color
    bg_opa=0,               # 0 = transparent background
    font=lv.font_montserrat_24,
    parent=page0,
)
```

Labels are read-only text — but "read-only" doesn't mean "static". Any
label's text can be changed at runtime with `set_text()`:

```python
title_label.set_text("Status: Ready")
```

This is how you'll show live status/feedback to the user — you don't
redraw the whole screen, you just update the one label that changed.

#### 3.2 `M5Button` — triggering actions

```python
order_button = m5ui.M5Button(
    text="Place Order",
    x=10, y=140, w=140, h=40,
    bg_c=0x2196F3,
    text_c=0xFFFFFF,
    font=lv.font_montserrat_14,
    parent=page0,
)

def order_button_clicked(event_struct):
    title_label.set_text("Order placed!")

def order_button_handler(event_struct):
    event = event_struct.code
    if event == lv.EVENT.CLICKED:
        order_button_clicked(event_struct)
    return

order_button.add_event_cb(order_button_handler, lv.EVENT.ALL, None)
```

Notice the pattern: **one handler function per widget**, registered once
with `add_event_cb`, which then dispatches to smaller functions based on
`event_struct.code`. You'll see this same shape everywhere in M5UI code —
including the official examples — so it's worth getting comfortable with
it now. Useful event codes for buttons: `lv.EVENT.PRESSED`,
`lv.EVENT.RELEASED`, `lv.EVENT.CLICKED`, `lv.EVENT.LONG_PRESSED`.

#### 3.3 `M5Checkbox` — and building a "radio button" from it

M5UI has no dedicated radio-button widget. Instead, you build radio-button
*behavior* out of a small group of checkboxes: when one gets checked, the
handler force-unchecks the others. This is a genuinely useful pattern —
you'll use it again in later labs — so let's build it properly.

```python
size_small  = m5ui.M5Checkbox(title="Small",  value=False, x=10,  y=100,
                               title_c=0x000000, title_font=lv.font_montserrat_14,
                               bullet_border_c=0x2196F3, bullet_bg_c=0xFFFFFF,
                               parent=page0)
size_medium = m5ui.M5Checkbox(title="Medium", value=False, x=110, y=100,
                               title_c=0x000000, title_font=lv.font_montserrat_14,
                               bullet_border_c=0x2196F3, bullet_bg_c=0xFFFFFF,
                               parent=page0)
size_large  = m5ui.M5Checkbox(title="Large",  value=False, x=210, y=100,
                               title_c=0x000000, title_font=lv.font_montserrat_14,
                               bullet_border_c=0x2196F3, bullet_bg_c=0xFFFFFF,
                               parent=page0)

def make_radio_handler(this_box, other_boxes):
    """Returns an event handler that turns `this_box` into part of a
    radio group: checking it unchecks every box in `other_boxes`."""
    def handler(event_struct):
        if event_struct.code == lv.EVENT.VALUE_CHANGED:
            if this_box.has_state(lv.STATE.CHECKED):
                for box in other_boxes:
                    box.set_state(lv.STATE.CHECKED, False)
    return handler

size_small.add_event_cb(
    make_radio_handler(size_small, [size_medium, size_large]), lv.EVENT.ALL, None)
size_medium.add_event_cb(
    make_radio_handler(size_medium, [size_small, size_large]), lv.EVENT.ALL, None)
size_large.add_event_cb(
    make_radio_handler(size_large, [size_small, size_medium]), lv.EVENT.ALL, None)
```

`make_radio_handler` is a **closure factory** — a function that builds and
returns a customized handler function for each checkbox. This avoids
writing three nearly-identical handler functions by hand. You'll find this
pattern useful any time you have several widgets that need "the same
logic, but about themselves."

Note what this *doesn't* do: it doesn't force one box to always be
checked. Tapping the only checked box will still uncheck it, leaving
*no* box selected — which is a valid, real state your program has to
handle (you'll need this in the lab).

#### 3.4 `M5TextArea` + `M5Keyboard` — text entry

The CoreS3 has no physical keyboard, so any text-entry field needs an
on-screen keyboard that appears when the field is focused and disappears
when it isn't.

```python
name_area = m5ui.M5TextArea(
    text="",
    placeholder="Enter your name...",
    x=10, y=44, w=300, h=40,
    parent=page0,
)

keyboard0 = m5ui.M5Keyboard(
    x=0, y=140, w=320, h=100,
    target_textarea=name_area,   # keyboard types directly into this field
    parent=page0,
)
keyboard0.set_flag(lv.obj.FLAG.HIDDEN, True)   # start hidden

def name_area_focused(event_struct):
    keyboard0.set_flag(lv.obj.FLAG.HIDDEN, False)

def name_area_defocused(event_struct):
    keyboard0.set_flag(lv.obj.FLAG.HIDDEN, True)

def name_area_handler(event_struct):
    event = event_struct.code
    if event == lv.EVENT.FOCUSED:
        name_area_focused(event_struct)
    if event == lv.EVENT.DEFOCUSED:
        name_area_defocused(event_struct)
    return

name_area.add_event_cb(name_area_handler, lv.EVENT.ALL, None)
```

Reading what the user typed is just `name_area.get_text()`, and clearing
it is `name_area.set_text("")`.

#### 3.5 Raw Touch — going underneath the widgets

Every widget event you've used so far is really built on top of one
thing: the touch controller reporting where a finger is on the glass.
You can read that directly:

```python
def loop():
    M5.update()
    if M5.Touch.getCount():
        x = M5.Touch.getX()
        y = M5.Touch.getY()
        print("Touched at:", x, y)
```

`M5.Touch.getCount()` tells you how many touch points are currently
active (0 or 1 on CoreS3 — it's single-touch hardware), and `getX()` /
`getY()` give you the most recent touch coordinates in screen-pixel
space. You won't need this for most UI work — the widget event system
handles the coordinate math for you — but it's the right tool when you
want to draw freehand, build a custom gesture, or detect a touch
*outside* of any widget's boundary.

### 4. Full Worked Example: Coffee Order Kiosk

This program ties every widget above into one working screen: a title, a
name field with keyboard, a mutually-exclusive size selector, and a
button that updates a status label. Copy this onto your CoreS3 and run it
before starting the lab — make sure you understand *every* line, because
Lab 3 asks you to build something structurally similar from a written
spec, not from this code.

```python
# SPDX-License-Identifier: MIT
#
# PRG455 Lecture 3 -- Coffee Order Kiosk
# Demonstrates M5Label, M5Button, M5Checkbox (as a radio group),
# M5TextArea + M5Keyboard, all driven by touch.

import os, sys, io
import M5
from M5 import *
import m5ui
import lvgl as lv

page0 = None
title_label = None
name_area = None
keyboard0 = None
size_small = None
size_medium = None
size_large = None
order_button = None
status_label = None


def make_radio_handler(this_box, other_boxes):
    def handler(event_struct):
        if event_struct.code == lv.EVENT.VALUE_CHANGED:
            if this_box.has_state(lv.STATE.CHECKED):
                for box in other_boxes:
                    box.set_state(lv.STATE.CHECKED, False)
    return handler


def name_area_focused(event_struct):
    keyboard0.set_flag(lv.obj.FLAG.HIDDEN, False)


def name_area_defocused(event_struct):
    keyboard0.set_flag(lv.obj.FLAG.HIDDEN, True)


def name_area_handler(event_struct):
    event = event_struct.code
    if event == lv.EVENT.FOCUSED:
        name_area_focused(event_struct)
    if event == lv.EVENT.DEFOCUSED:
        name_area_defocused(event_struct)
    return


def selected_size():
    if size_small.has_state(lv.STATE.CHECKED):
        return "Small"
    if size_medium.has_state(lv.STATE.CHECKED):
        return "Medium"
    if size_large.has_state(lv.STATE.CHECKED):
        return "Large"
    return None


def order_button_clicked(event_struct):
    name = name_area.get_text()
    size = selected_size()
    if name and size:
        status_label.set_text("Order for %s: %s coffee" % (name, size))
    else:
        status_label.set_text("Enter a name and pick a size first")


def order_button_handler(event_struct):
    if event_struct.code == lv.EVENT.CLICKED:
        order_button_clicked(event_struct)
    return


def setup():
    global page0, title_label, name_area, keyboard0
    global size_small, size_medium, size_large, order_button, status_label

    M5.begin()
    Widgets.setRotation(1)
    m5ui.init()
    page0 = m5ui.M5Page(bg_c=0xFFFFFF)

    title_label = m5ui.M5Label(
        "Coffee Order Kiosk", x=10, y=6,
        text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
        font=lv.font_montserrat_20, parent=page0,
    )

    name_area = m5ui.M5TextArea(
        text="", placeholder="Enter your name...",
        x=10, y=36, w=300, h=36, parent=page0,
    )
    name_area.add_event_cb(name_area_handler, lv.EVENT.ALL, None)

    keyboard0 = m5ui.M5Keyboard(
        x=0, y=140, w=320, h=100,
        target_textarea=name_area, parent=page0,
    )
    keyboard0.set_flag(lv.obj.FLAG.HIDDEN, True)

    size_small = m5ui.M5Checkbox(
        title="Small", value=False, x=10, y=82,
        title_c=0x000000, title_font=lv.font_montserrat_14,
        bullet_border_c=0x2196F3, bullet_bg_c=0xFFFFFF, parent=page0,
    )
    size_medium = m5ui.M5Checkbox(
        title="Medium", value=False, x=110, y=82,
        title_c=0x000000, title_font=lv.font_montserrat_14,
        bullet_border_c=0x2196F3, bullet_bg_c=0xFFFFFF, parent=page0,
    )
    size_large = m5ui.M5Checkbox(
        title="Large", value=False, x=210, y=82,
        title_c=0x000000, title_font=lv.font_montserrat_14,
        bullet_border_c=0x2196F3, bullet_bg_c=0xFFFFFF, parent=page0,
    )
    size_small.add_event_cb(
        make_radio_handler(size_small, [size_medium, size_large]), lv.EVENT.ALL, None)
    size_medium.add_event_cb(
        make_radio_handler(size_medium, [size_small, size_large]), lv.EVENT.ALL, None)
    size_large.add_event_cb(
        make_radio_handler(size_large, [size_small, size_medium]), lv.EVENT.ALL, None)

    order_button = m5ui.M5Button(
        text="Place Order", x=10, y=190, w=140, h=36,
        bg_c=0x2196F3, text_c=0xFFFFFF,
        font=lv.font_montserrat_14, parent=page0,
    )
    order_button.add_event_cb(order_button_handler, lv.EVENT.ALL, None)

    status_label = m5ui.M5Label(
        "", x=160, y=196,
        text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
        font=lv.font_montserrat_14, parent=page0,
    )

    page0.screen_load()


def loop():
    M5.update()


if __name__ == '__main__':
    try:
        setup()
        while True:
            loop()
    except (Exception, KeyboardInterrupt) as e:
        try:
            m5ui.deinit()
            from utility import print_error_msg
            print_error_msg(e)
        except ImportError:
            print("please update to latest firmware")
```

Run it. Type a name, tap between Small/Medium/Large and confirm only one
stays checked at a time, then tap Place Order — with and without a name
or size entered — and watch the status label respond both ways.

### 5. Key Takeaways

- M5UI, not Tkinter, is what actually runs on the CoreS3 — same
  widgets-and-events mental model, different library.
- Every program: `M5.begin()` → `m5ui.init()` → build widgets with
  `parent=` → `page0.screen_load()` → loop calling `M5.update()`.
- Events are handled by **one dispatcher function per widget**,
  registered with `add_event_cb(handler, lv.EVENT.ALL, None)`, which
  checks `event_struct.code` to decide what happened.
- There's no built-in radio button — you compose one from `M5Checkbox`
  widgets and a shared "uncheck the others" handler.
- `M5TextArea` needs a paired `M5Keyboard` shown/hidden on
  `FOCUSED`/`DEFOCUSED`, since there's no physical keyboard.
- `M5.Touch.getCount()/getX()/getY()` gives you raw touch coordinates
  when you need to go beneath the widget layer.
